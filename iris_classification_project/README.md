

A production-style implementation of the DecodeLabs Project 2 requirements:

- Load and inspect a small classification dataset
- Use an 80/20 train-test split
- Prevent data leakage with a `Pipeline`
- Standardize numerical features
- Train a K-Nearest Neighbors (KNN) classifier
- Tune `k` using stratified cross-validation
- Evaluate using accuracy, precision, recall, F1, and a confusion matrix
- Save the trained model and evaluation artifacts
- Support prediction on new flower measurements
- Include automated tests

## Dataset

The project uses the classic Iris dataset provided by scikit-learn:

- 150 samples
- 3 classes: setosa, versicolor, virginica
- 4 numerical features:
  - sepal length (cm)
  - sepal width (cm)
  - petal length (cm)
  - petal width (cm)

The assignment material explicitly presents Iris, feature scaling, an 80/20 split, KNN, confusion matrix, and F1 score as the core pipeline.

## Setup

Python 3.10+ is recommended.

```bash
python -m venv .venv
```

Windows:

```bash
.venv\Scripts\activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

## Train

From the project root:

```bash
python -m src.train
```

The training script:

1. Loads Iris.
2. Saves a CSV copy to `data/iris.csv`.
3. Performs a stratified 80/20 train-test split.
4. Builds `StandardScaler -> KNN`.
5. Selects the best `k` using 5-fold stratified cross-validation on training data only.
6. Evaluates the final pipeline on the untouched test set.
7. Saves the model to `models/iris_knn_pipeline.joblib`.
8. Saves metrics to `reports/metrics.json`.

## Predict new data

Example:

```bash
python -m src.predict --sepal-length 5.1 --sepal-width 3.5 --petal-length 1.4 --petal-width 0.2
```

## Why this is more industry-ready than a basic classroom implementation

The core assignment is intentionally simple, but the implementation follows practical ML engineering habits:

- preprocessing is inside the model pipeline, so training and inference use the same transformations;
- scaling is fitted only on training data;
- the test set is held out until final evaluation;
- stratification preserves class proportions;
- hyperparameter selection uses cross-validation rather than choosing `k` from the test set;
- metrics include more than accuracy;
- the trained artifact can be reused for inference;
- tests verify the pipeline and prediction behavior;
- results are written to machine-readable JSON for reproducibility.

This keeps the project faithful to the assignment while making the code clean enough to demonstrate professional ML workflow.
